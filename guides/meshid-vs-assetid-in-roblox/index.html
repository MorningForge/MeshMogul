MeshId vs AssetId in Roblox

Learn how Roblox asset IDs relate to MeshPart.MeshId and why a model ID, image ID, and logical asset record are different.

Keep in mind. Editorial draft. Check the current Studio interface and your asset permissions. MeshMogul steps apply only to supported inputs.

AssetId is a general identifier.

Roblox uses asset IDs for different kinds of published content. A mesh, an image, and a model can each have an asset ID, but that does not make their IDs interchangeable. Always know what asset type a number refers to.

MeshId identifies mesh geometry.

On a MeshPart, MeshId is the content reference for its geometry. When it points to a published mesh, its numeric component identifies that mesh asset. It is not the same thing as the MeshPart instance, its parent Model, or a Creator Store listing for a container.

A reference such as rbxassetid://1234567890 illustrates the URI form. The value shown here is only an example. Temporary object-backed content is a separate case and should not be treated as a confirmed durable asset ID.

Geometry is only part of the result.

A mesh ID alone does not describe every property of the MeshPart you see in Studio. Color, material, texture references, transparency, and appearance objects may be applied separately. Image asset IDs identify image content, not geometry.

Where MeshMogul fits.

MeshMogul’s logical asset record binds one or more ordered physical mesh asset IDs with supported appearance information and a shared placement relationship. A single logical asset is a library concept; it does not imply a new single Roblox mesh ID for the whole group.

Use the complete Assets record to insert the logical result. An incomplete grouped publication cannot Insert. Removing that local record does not delete its Roblox assets.

An ID is not permission or an update mechanism.

Knowing the number does not grant loading rights. Likewise, keeping an ID in a record does not mean MeshMogul can replace its content: same-AssetId updates are not a shipped MeshMogul workflow.

Source references and published outputs.

MeshMogul 1.1.1 provides ordered source MeshId references with copy support. These identify the source geometry, not the new output assets. Complete grouped Assets records retain their ordered confirmed output IDs for reuse. A copied source reference is neither publication confirmation nor permission to use that asset.
