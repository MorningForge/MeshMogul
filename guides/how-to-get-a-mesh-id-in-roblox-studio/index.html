How to Get a Mesh ID in Roblox Studio

Find a real MeshId in Explorer in under 30 seconds—and stop copying texture IDs, Model IDs, or temporary session previews by mistake.

Quick Takeaways

  • Why it matters: Only geometry objects that reference a mesh asset (MeshPart.MeshId or SpecialMesh.MeshId) store a MeshId .
  • How it affects your creations: Confusing MeshId with TextureID, a Creator Store model URL, or an in-session temporary preview breaks scripts, AssetService tools, and cross-place reuse.
  • What you can actually do about it: Expand the Model in Explorer, select the MeshPart itself, copy its rbxassetid://... value (or inspect all child MeshParts via the Command Bar), and verify permissions before reusing it across experiences.

If you click a prop in Studio's viewport and look at the Properties window expecting a MeshId box to magically appear, two things usually go wrong:

  1. You selected the parent Model instead of the MeshPart inside it—so MeshId is nowhere to be found.
  2. You selected a regular Part (Block, Wedge, Cylinder, Ball)—which uses procedural engine shapes rather than a MeshId.

Here is how to grab the exact MeshId Roblox renders, check that it is durable, and inspect multi-part meshes cleanly.

1. The 4-Step Studio Method

  1. Open Explorer (View -> Explorer) and Properties (View -> Properties).
  2. Click the prop in the viewport, then check Explorer: if Studio highlighted a Model or Folder, click the arrow beside it to expand its children.
  3. Select an actual MeshPart child inside that hierarchy.
  4. In Properties, scroll to MeshId (under Data or search MeshId in the Properties filter bar). You should see a durable URI formatted like rbxassetid://1234567890 (example placeholder).

Watch out for SpecialMesh: Older accessories, hats, or legacy props sometimes place a SpecialMesh inside a regular Part. In that case, MeshId lives on the SpecialMesh child rather than the Part itself .

2. Four IDs That Look Similar—and Break Things When Swapped

What You Copied What It Actually Is Safe to Put in MeshPart.MeshId?
MeshPart.MeshId (rbxassetid://...) The published triangle geometry asset Yes (assuming your experience has asset permission)
MeshPart.TextureID (rbxassetid://...) A 2D surface image texture No — images are not 3D geometry
Creator Store / Toolbox Model URL A container Model asset (often wrapping scripts, parts, or several MeshParts) No — insert the model first, then expand it to read child MeshPart.MeshId values
Retained Preview (Object-backed EditableMesh) Live local session preview memory inside Studio No — must be published first to receive a durable cloud rbxassetid://...

Permissions reminder: Even when a MeshId is completely valid, Roblox restricts private mesh reuse across creators or groups unless permissions allow it (MeshId vs AssetId in Roblox).

3. Read-Only Command Bar Snippet: List Every MeshId Inside a Selection

When a prop holds five or ten MeshParts (for example, a multi-material building facade), clicking one by one gets old fast. Select the parent Model in Explorer and paste this read-only check into Studio's Command Bar (View -> Command Bar):

Read-only Studio Command Bar inspection

-- Read-only: lists every MeshPart (or SpecialMesh) MeshId under the current Explorer selection
local Selection = game:GetService("Selection")
local selected = Selection:Get()

if #selected == 0 then
    warn("Select a Model, MeshPart, or SpecialMesh in Explorer first.")
    return
end

local function inspectRoot(root: Instance)
    local candidates = root:GetDescendants()
    table.insert(candidates, 1, root)

    local found = 0
    for _, inst in ipairs(candidates) do
        if inst:IsA("MeshPart") then
            found += 1
            local id = inst.MeshId ~= "" and inst.MeshId or "(empty or Object-backed preview)"
            print(string.format("[MeshPart] %s -> MeshId=%s | TextureID=%s", inst:GetFullName(), id, inst.TextureID))
        elseif inst:IsA("SpecialMesh") and inst.MeshType == Enum.MeshType.FileMesh then
            found += 1
            print(string.format("[SpecialMesh] %s -> MeshId=%s | TextureId=%s", inst:GetFullName(), inst.MeshId, inst.TextureId))
        end
    end

    if found == 0 then
        print("No MeshPart or FileMesh SpecialMesh instances found under " .. root.Name)
    end
end

for _, root in ipairs(selected) do
    inspectRoot(root)
end

Notice what this reveals immediately: if a MeshPart is still an unsaved in-session EditableMesh preview, inst.MeshId prints as empty—so you never mistake a local preview for a cloud-backed asset.

4. Copying Ordered IDs in MeshMogul

If you built and published the asset through MeshMogul:

  • Complete records in MeshMogul's Assets tab store the ordered list of output MeshIds created for that logical asset, plus source-reference IDs when you baked from existing MeshParts (How MeshMogul Works).
  • You can inspect and copy those output MeshIds right from the complete record instead of digging back through Explorer every time you need an ID for a script, Content reference, or documentation note.
  • Incomplete records under Needs attention still show any already-confirmed IDs, while blocking Insert until the remaining publication steps finish cleanly.
