Roblox Studio guide

Prepare Roblox Assistant and ProceduralModel Output for Reuse

Identify what Assistant created, finish generation, and keep an editable original before making a reusable visual mesh.

Start with the object in Explorer. Assistant can create code, procedural models, and meshes. Each needs a different next step. The checks below also work without MeshMogul.

1. Identify the output

Expand the result in Explorer and select its root. A Model groups instances; a MeshPart displays mesh geometry; a ProceduralModel regenerates content from a Generator ModuleScript and parameters. A script by itself is none of these. Review generated code before running it.

Assistant can generate meshes and procedural models, and Roblox’s Studio MCP server connects external AI clients to Studio tools. Those Roblox capabilities do not mean MeshMogul runs an AI client, approves generated code, or publishes on your behalf.

2. Make a small, editable example

For a native starting point, insert a ProceduralModel into Workspace through Explorer. Roblox supplies a template generator. Inspect its Generator and exposed parameters before changing them. Alternatively, ask Assistant for a small procedural prop with named components and a few adjustable dimensions. Treat the response as a starting point to review, not a guaranteed result.

  1. Keep the original procedural model and Generator in your project.
  2. Change one exposed parameter at a time. A change to Size, attributes, or generator code can trigger regeneration; generation may finish after the property change.
  3. Wait for the result to settle. Check GenerationError in Properties if generation fails. An error placeholder or empty result is not finished geometry.
  4. Expand the generated contents. Check shapes, materials, textures, and any scripts or other behavior separately.
  5. Decide which pieces need to remain separately movable. Keep that editable organization in the original, even if you later create a combined visual mesh.

Roblox documents WaitForGenerationAsync() for code that must wait for completion. A successful generation means the generator finished; it does not certify the appearance, compatibility, or performance of its output. See procedural models and the ProceduralModel API.

3. Choose what to preserve

Keep the procedural original when you need adjustable dimensions or future regeneration. Keep a normal Model when scripts, constraints, hierarchy, or gameplay behavior matter. A frozen visual mesh captures a shape; it does not retain those behaviors or the Generator’s parameters.

If the output is already a usable MeshPart, inspect its geometry and texture references before adding a conversion step. A MeshId identifies geometry, not a complete editable asset or every appearance setting.

4. Use MeshMogul only for compatible geometry

For a supported ProceduralModel, MeshMogul waits for current generated BaseParts to stabilize and creates a frozen visual result while retaining the source and Generator. Empty, failed, nested, detached, or stale generation is refused. A regular Model follows the normal container rules; unsupported descendants block the selected root.

  1. Select one supported root and read the compatibility messages. MeshMogul 1.3.0 includes supported solid Union/CSG mixed assemblies and transparent Glass Union workflows. Not every generated assembly is compatible; child Decal/Texture overlays and unreadable meshes remain unsupported.
  2. Create Preview and compare geometry, shading, placement, and both sides with the original. Multiple supported appearances may produce several meshes in one grouped result.
  3. If generation or the source changes, create and inspect a fresh Preview. Publication must use the exact approved retained result.
  4. Check the creator destination and permissions. Review and manually run the current generated command in Studio’s Command Bar only when ready to upload.
  5. Wait for every output to confirm. Insert from the complete local Assets record, then compare the inserted result with the original.

MeshMogul does not copy source scripts, constraints, animation, hierarchy, or physics behavior into the visual derivative. Local Assets is not a backup of the editable source or a cloud sync service.
