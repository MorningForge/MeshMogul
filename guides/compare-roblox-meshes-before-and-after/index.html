How to Compare Roblox Meshes Before and After Conversion

Verify visual fidelity, pivot alignment, collision geometry, and real rendering impact before you swap a single asset across your map.

Quick Takeaways

  • Why it matters: Mesh conversion changes how Roblox stores geometry, assigns material groups, simplifies distant LODs (RenderFidelity), and builds physics shapes (CollisionFidelity) .
  • How it affects your creations: Deleting the original build prematurely—or comparing without matching lighting, distance, and collision overlays—hides backface defects, scale drift, and wasted physics memory .
  • What you can actually do about it: Compare three exact stages side by side, run six fast visual checks, inspect collision hulls directly in Studio, and measure real A/B scene cost in the MicroProfiler (Ctrl+F6) before declaring an optimization win.

"Looks good from ten studs away" has broken more Roblox props than any plugin bug ever written. Backface holes only show up when you orbit behind a railing; grazing sunlight exposes creased shading you never noticed at noon; RenderFidelity.Automatic simplifies thin silhouettes at 250 studs; and CollisionFidelity defaults silently turn doorways into solid brick walls.

Do not eyeball a single prop in place and guess whether your conversion improved it. Put the Original, Preview, and Published builds side by side on a clean test bench and check what Studio's eyes and profiler actually report.

1. Set Up a 3-Stage Comparison Bench

Drop all three versions of your prop along a straight flat line on a neutral baseplate, spaced cleanly apart (for example, 12 studs apart) at the exact same ground height:

  1. 01_Source_Original: Your editable part-built Model or pre-conversion asset.
  2. 02_Preview_InSession: The local retained Preview before cloud publication (for example, an EditableMesh preview).
  3. 03_Published_Inserted: The durable cloud-backed asset inserted back from its published MeshIds.

Why all three? Because comparing 01 vs 02 verifies geometry conversion accuracy before you spend an upload, while comparing 02 vs 03 confirms publication, asset references, MaterialVariants, and DoubleSided survived the trip to the cloud.

Read-Only Command Bar Inventory Audit

Select all three models (or folders) in Explorer and run this read-only Command Bar check to inspect exact instance counts, primitive vs MeshPart mix, and MeshId durability side by side:

Read-only Studio Command Bar inspection

-- Read-only: summarizes BasePart/MeshPart structure and cloud MeshId status per selected root
local Selection = game:GetService("Selection")
local selected = Selection:Get()

if #selected == 0 then
    warn("Select your Original, Preview, and Published roots in Explorer first.")
    return
end

for _, root in ipairs(selected) do
    local baseParts, meshParts, unions, missingCloudIds = 0, 0, 0, 0
    local list = root:GetDescendants()
    table.insert(list, 1, root)

    for _, inst in ipairs(list) do
        if inst:IsA("BasePart") then
            baseParts += 1
            if inst:IsA("MeshPart") then
                meshParts += 1
                if inst.MeshId == "" then
                    missingCloudIds += 1
                end
            elseif inst:IsA("UnionOperation") then
                unions += 1
            end
        end
    end

    print(string.format(
        "[Bench] %-22s | BaseParts=%d | MeshParts=%d | Unions=%d | EmptyMeshId=%d",
        root.Name, baseParts, meshParts, unions, missingCloudIds
    ))
end

2. Six Fast Visual Checks (Takes Under Two Minutes)

Run through these six visual checks while orbiting 01, 02, and 03:

  1. Neutral Clay Check (Material Parity): Temporarily test bright flat lighting without heavy color saturation so silhouette defects, z-fighting planes, or misplaced bevels jump straight out.
  2. Grazing Sunlight (ClockTime 6.5 to 17.5): Drag Lighting.ClockTime toward sunrise (6.5) and late afternoon (17.5). Low grazing rays reveal smooth-vs-flat shading breaks, welded seams, and normal artifacts invisible under flat noon light.
  3. Backface & DoubleSided Orbit: Orbit underneath and inside open arches, canopies, or thin panels. If a face disappears from behind, inspect winding—do not casually mask missing thickness with DoubleSided = true unless thin single-sided leaves/cloth truly require it.
  4. MaterialVariant and SurfaceAppearance Check: Confirm mapped surfaces align cleanly and custom mapless MaterialVariant names still match entries in MaterialService.
  5. Cloud URI Durability Check: Confirm 03_Published_Inserted reports real rbxassetid://... MeshIds (EmptyMeshId=0 in the script above) rather than blank preview content.
  6. Distance LOD Check (RenderFidelity.Automatic): Under Roblox's documented RenderFidelity.Automatic thresholds, Studio keeps full detail closer than 250 studs, transitions to medium detail around 250–500 studs, and switches to lowest detail past 500 studs . Fly the Studio camera back across 250 and 500 studs to make sure narrow railings or thin signs don't collapse weirdly before choosing Precise vs Automatic.

3. Audit Collision Shapes and Hidden Physics Memory

Never assume "it looks identical" means "it walks identical."

  1. In Studio's viewport Visualization Options, toggle Collision fidelity on .
  2. Walk or raycast through tight openings, stairs, and arches between 01 and 03.
  3. Watch for Default or Hull filling in doorways (if an opening gets shrink-wrapped shut, read Collision Fidelity and Invisible Doorways).
  4. Remember physics memory: Roblox still generates and retains PhysicsParts collision memory for non-Box MeshParts even when CanCollide = false (because CanQuery and CanTouch still use collision hulls unless explicitly disabled or boxed) . Set CollisionFidelity = Enum.CollisionFidelity.Box on purely decorative meshes that never need accurate raycasts or touches.

4. Four Performance Metrics That Don't Lie

Before claiming a conversion "made the game faster," separate four independent costs:

Cost Dimension What Changes When Converting Parts -> MeshPart(s) How to Verify Real Impact
Instance & Tree Overhead One 80-part prop might drop to 1–4 MeshParts (smaller Explorer replication/hierarchy) Compare BaseParts count in the script above
Triangle & Vertex Budget Internal hidden faces can be eliminated—or spherical parts can stay expensive if overused Inspect Studio Render stats & mesh budgets (Draw Calls, Instancing, and Hidden Faces)
Draw Calls & GPU Batching Splitting 1 prop into 4 material groups can add state switches, while repeating 500 identical props lets Roblox instance them cleanly Test realistic counts (e.g., 100 copies in an empty test place)
Frame Time Breakdown (MicroProfiler) Tells whether your bottleneck is actually GPU/render work vs scripts/physics Open MicroProfiler (Ctrl+F6) and compare Blue (Render > Jobs) vs Red (GPU Wait Time > 2.5 ms) bars across identical camera angles

Measurement check: Never trust an "FPS boost" claim measured by standing still looking at a single converted barrel. Test a representative cluster of props with identical camera framing, identical lighting, and both versions tested on clean baseplates.

5. MeshMogul Comparison Workflow

If you converted the asset with MeshMogul:

  • Keep your original build in ServerStorage (or right beside the test bench) until 03_Published_Inserted passes every visual, pivot, and collision check.
  • Use MeshMogul's Assets Insert button to spawn the clean cloud-backed asset directly into your bench, and use exact-instance Find when locating tracked inserted copies inside the open place (Turn a Roblox Studio Model Into a Reusable Mesh Asset).
  • If an incomplete publish sits in Needs attention, fix the publish before judging final cloud parity.
