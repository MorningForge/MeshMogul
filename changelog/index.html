Proposed update · not yet released

1.2.0 · provisional

This candidate is prepared for review. The final version and Creator Store release are not yet confirmed.

  • Two-sided MeshPart fidelity. Supported DoubleSided appearance is retained through Preview and reuse, including a verified textured case published and reinserted in a fresh Studio session.
  • Supported appearance grouping. Compatible outputs retain their own appearance and sidedness rather than forcing incompatible states together.
  • Clearer boundaries. Inspect the result and resolve unreadable or unsupported content before publishing. Texture, UV, normals and vertex color preservation depend on the supported source and available data.

Grouped outputs, Assets, publication safeguards, references and navigation were already advertised in 1.1.1. This update does not promise universal PBR or texture fidelity, skinned-pose conversion, direct Union/CSG conversion, or same-ID updates.

Current release

Founding · 1.1.1

MeshMogul 1.1.1 is available on Roblox Creator Store. Review these changes here or in the plugin’s What’s New panel.

  • Multiple appearance outputs. Supported appearance groups can produce ordered meshes within one logical result.
  • Grouped Preview and Assets. Inspect the retained result and reuse complete grouped records while preserving original source.
  • Improved supported appearance preservation. Material, transparency, color and surface distinctions have explicit compatibility boundaries, not a universal PBR or arbitrary texture-baking guarantee.
  • Safer publication. Source-freshness checks guard against stale source; partial outcomes retain confirmed IDs without treating incomplete results as ready to Insert.
  • Ordered source MeshId references. Copy source references while keeping them distinct from confirmed published output IDs.
  • Inspection and navigation. Improved inspection, exact-instance Find for the tracked inserted root in the current place, and Reset Position for Preview inspection.
  • What’s New in the plugin. Review release changes inside Studio.
  • Release presentation and notices. Header mascot branding and bundled third-party notices. Read the public legal and notices page.

Publication remains an explicit guided Studio Command Bar handoff. Direct Union conversion, automatic publishing, same-ID updates, team/cloud sync and guaranteed optimization are not included.

Earlier notes · 1.1.0

Founding · 1.1.0

These earlier 1.1.0 notes are retained as history. They describe the previous release-panel summary; no historical public release date is assigned here. See the 1.1.1 section above for the current release.

  • Multi-output meshes. Supported appearance groups can produce ordered physical outputs within one logical result.
  • Grouped Preview. Multi-output results remain one logical Preview for inspection.
  • Appearance separation. Compatible material and transparency states can remain separate instead of being forced into an invalid single output.
  • Grouped Assets lifecycle. One record remembers and reinserts its ordered mesh IDs.
  • Primitive surface shading. Explicit normals preserve hard and smooth shading on supported converted primitives; this is not a universal appearance guarantee.
  • Preview inspection. Select Preview, inspect with Studio Move/Rotate, and use Reset Position to restore the approved position and angle.
  • Partial-publication state. Confirmed partial results are kept; an incomplete grouped publication is not presented as complete or blindly retried.

The Founding workflow

Build → Preview → Publish → Remember → Reuse. Original source is retained, publication uses an explicit manual Studio Command Bar handoff, and remembered Assets are local plugin settings.

Direct Unions, arbitrary PBR fidelity, automatic same-ID updates, and team/cloud sync are not part of the current promise. Read current compatibility and limits.
