Workflow

From build to reusable asset.

Keep building in Roblox Studio. Use MeshMogul when a supported result is ready for inspection and reuse.

01 / Build & select

Start with one supported root.

Select one supported BasePart or one container such as a Model or Folder. A container may hold multiple supported parts; selecting several independent roots is a different operation and is refused.

Preflight checks geometry, appearance, and output limits. An unsupported descendant blocks the root rather than silently dropping that piece. Start with a small primitive build and read the explanation before proceeding.

Review the full compatibility boundary →

02 / Preview

Inspect the retained result.

Preview Mesh creates a retained temporary visual derivative for inspection. One output is a MeshPart; several ordered outputs stay together as one logical Preview. Your original source is retained rather than permanently converted.

Use Select Preview and Studio Move/Rotate to inspect it. Reset Position restores the approved position and angle. Check the result in your intended lighting; copied properties are not a guarantee of identical rendering.

If you change the source or selection, prepare a fresh Preview before publishing. The publish step checks that it still matches the approved source.

03 / Publish

A deliberate Studio handoff.

Publish Mesh prepares an inspectable command. Review the destination and generated text, then manually run the current command in Studio’s Command Bar. This is a real upload action, separate from previewing.

Generating text is not proof of publication. Wait for confirmed results. For grouped output, each physical mesh is published in order. If the process only partially completes, confirmed IDs are kept and the logical asset remains incomplete.

Do not blindly rerun an expired or uncertain command. Read the current state and follow the plugin’s guidance. The workflow creates new mesh assets; it does not update an existing Mesh AssetId.

04–05 / Remember & reuse

Return to a complete asset.

Assets records store confirmed mesh IDs and supported appearance information in local plugin settings. Use Insert on a complete record to load a new copy; use exact-instance Find to locate the tracked inserted logical root in the current place. Find is not a search across every matching mesh or other places.

Incomplete records stay under Needs attention and cannot Insert. Removing a library record does not delete the Roblox assets. This library is not a cloud inventory, an ownership certificate, or a cross-device backup.

Copy source references with confidence.

In 1.1.1, ordered source MeshId references have copy support. These identify the source meshes; they are distinct from the newly published output mesh asset IDs stored in Assets. A primitive Part does not acquire a source MeshId merely by being selected.

Improved inspection and navigation help you review the current selection and Preview. Reset Position restores the approved Preview position and angle. The in-plugin What’s New panel explains release changes without leaving Studio.

Review both sides and the final result.

MeshMogul 1.2.0 improves supported DoubleSided MeshPart fidelity. One textured two-sided case was verified through publication and fresh-session reuse. Inspect front and back under your intended lighting; a supported example does not guarantee every texture or material.

One logical asset, multiple MeshIds.

A single mesh output cannot represent every combination of appearance states. MeshMogul can keep supported groups separate, with their own physical mesh IDs, while treating the result as one logical asset.

Insertion returns one MeshPart for a single output or one Model containing the ordered outputs. The grouping does not retain source scripts, constraints, hierarchy, or physics behavior. It is a visual derivative.
